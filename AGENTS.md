# AGENTS.md

Instructions for AI coding agents working in this repository.

## Repository overview

This is a collection of single-file browser-based tools hosted on GitHub Pages at **tools.stalhem.se**. Each tool is a standalone `.html` file in the repo root containing inline CSS and JavaScript. There are no server-side components — everything runs in the browser.

The repo includes a build system (Python scripts + GitHub Actions) that auto-generates an index page, a colophon, date metadata, and a shared navigation footer. Individual tool files should not depend on or modify any of this infrastructure.

## Creating a new tool

1. **Copy the starter template** from `.templates/tool.html` into the repo root.
2. **Rename it** using kebab-case: `my-tool-name.html`.
3. **Set the `<title>`** to a clear, human-readable name (e.g. "Word Count", "JSON Formatter"). The build extracts this for the site index.
4. **Optionally** create a companion `my-tool-name.docs.md` with a one-paragraph description of what the tool does.

### Reserved filenames

Do not use these names — they are generated by the build:

- `index.html`
- `colophon.html`
- `by-month.html`

## Design system

All tools must follow these values for visual consistency. The starter template in `.templates/tool.html` has these baked in.

| Token | Value |
|---|---|
| Font stack | `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif` |
| Primary text | `#111827` |
| Secondary text | `#6b7280` |
| Interactive / focus | `#2563eb` |
| Borders | `#d1d5db` |
| Dividers | `#e5e7eb` |
| Error text | `#991b1b` |
| Error background | `#fef2f2` |
| Border radius | `6px` |
| Focus ring | `border-color: #2563eb; box-shadow: 0 0 0 2px rgba(37, 99, 235, 0.15)` |
| Responsive breakpoint | `@media (max-width: 600px)` |

### Layout

- Default max-width is **640px**, centered with `margin: 2rem auto; padding: 0 1.5rem`.
- Complex or visual tools (dashboards, visualizations, side-by-side layouts) may widen to **900px** or **1200px** when the content demands it, but start at 640px and only go wider if there's a clear reason.

### CSS reset

Always include `* { box-sizing: border-box; }` at the top of the `<style>` block.

## Technology rules

**Do:**

- Write plain HTML, CSS, and vanilla JavaScript.
- Keep everything in a **single `.html` file** with inline `<style>` and `<script>` blocks.
- Load external JS libraries from a CDN when needed (prefer **jsdelivr** or **cdnjs**), via `<script>` tag or ES module import.

**Don't:**

- No frameworks — no React, Vue, Svelte, Angular, etc.
- No CSS frameworks — no Tailwind, Bootstrap, etc.
- No build tools, bundlers, or transpilers per tool.
- No TypeScript — write plain JavaScript.

## JavaScript best practices

- **Prefer real-time feedback.** Process input on `input` events rather than requiring a button click, when practical.
- **Copy to clipboard.** Use `navigator.clipboard.writeText()`. Show brief "Copied!" feedback (1.5–2 seconds), then reset the button text.
- **Error display.** Use a hidden `.error` element toggled with a `.visible` class. Style with the error colors from the design system.
- **File handling.** Support both click-to-select and drag-and-drop. Always call `e.preventDefault()` on `dragover` and `drop` events.
- **Show/hide.** Toggle a `.visible` class rather than setting `style.display` directly.
- **Loading states.** Disable the trigger button and update its text while async work runs. Restore both in a `finally` block.
- **Scope.** Prefer `const` and `let` over `var`. Use `type="module"` or an IIFE to avoid polluting the global namespace when the tool has substantial logic.

## Build system — do not touch

The build system runs automatically on deploy. Be aware of how it works, but do not modify it.

- **`footer.js`** is automatically injected before `</body>` during the build. Never include it manually in tool files.
- **`gather_links.py`** reads each tool's `<title>` tag for the site index — this is why the title matters.
- **`build.sh`** generates `index.html`, `colophon.html`, `by-month.html`, `dates.json`, and `tools.json`.
- **Do not modify:** `build.sh`, `build_*.py`, `gather_links.py`, `site.json`, `footer.js`, `deploy.yml`, or the comment placeholders in `README.md`.

## Dark mode compatibility

The auto-injected footer detects the page's background luminance and adapts its own colors. Avoid hardcoding a white background on `<body>` unless the tool specifically requires it. Keep color choices compatible with potential future dark mode support.

## Accessibility

- Use semantic HTML: `<label>`, `<button>`, `<input>`, headings in proper order.
- Associate `<label>` elements with their inputs using `for`/`id`.
- Ensure all interactive elements are keyboard-accessible.
- Use meaningful `placeholder` text on inputs.

## Testing locally

```bash
python3 -m http.server 8000
```

Open `http://localhost:8000/my-tool.html` and verify:

- The tool works as expected.
- The layout is responsive at narrow viewport widths.
- There are no console errors.
